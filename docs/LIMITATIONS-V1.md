# Limites de Maison OS 1.3

- Les retours utilisateur ont validé le diagnostic sur sa tablette et au moins la vidéo/PTZ d’une caméra. La seconde caméra est désormais découverte en DVRIP/RTSP selon le retour utilisateur ; son authentification, son format RTSP et son ONVIF restent à vérifier.
- Le matériel domestique est inaccessible depuis le cloud. Les tests JVM et émulateur ne certifient ni les caméras réelles, ni l’audio audible, ni la stabilité prolongée sur Android 16.
- Pas de serveur ni de Home Assistant requis. Pas encore de capteurs HTTP/MQTT externes, QR iCSee, vidéo DVRIP, audio caméra bidirectionnel, presets PTZ, synchronisation cloud Smart Life, Tesla ou calendrier familial. Le courrier et les tests manuels restent explicitement simulés.
- Les destinations caméra sont des IPv4 privées littérales. Pas de DNS/IPv6 ni de découverte exhaustive à travers VLAN/réseaux invités. Le scan approfondi vise le segment /24 de l’IPv4 Wi-Fi et les ports habituels DVRIP/RTSP ; les ports personnalisés sont configurables manuellement.
- ONVIF : sous-ensemble Profile S, profil de plus petite résolution annoncée (premier si inconnue), WSSE UsernameToken Digest et HTTP Digest MD5/SHA-256 qop auth. L’horloge caméra doit être correcte. Le service initial est HTTP ; les services HTTPS annoncés gardent la vérification TLS standard. Les URLs visant un autre hôte sont refusées.
- RTSP et DVRIP dépendent du firmware, des identifiants et des codecs. Deux flux par défaut, deux au maximum dans les widgets ; préférer les sous-flux. Les reprises RTSP sont bornées, les réauthentifications DVRIP sont manuelles et limitées.
- Un STOP PTZ acquitté n’est pas une preuve d’arrêt mécanique. Une rupture réseau ou la mort du processus peut empêcher STOP ; le timeout ONVIF doit aussi être respecté par la caméra. Le STOP de compatibilité DVRIP n’est pas universel. Conserver la réserve documentée dans l’ancienne preuve de faisabilité.
- La présence est une détection de variation de luminance, avec faux positifs possibles, au premier plan uniquement. La veille est noire logiciellement ; aucune extinction physique ni protection Android contournée.
- L’adhan exact exige l’autorisation Android correspondante. Sans elle, programmation approximative et lancement audio en arrière-plan non garanti. Notifications, mode Ne pas déranger, batterie et restrictions constructeur peuvent modifier le résultat : tester sur la tablette. Le boot ne démarre jamais de caméra ni de service audio ; il restaure les alarmes futures après déverrouillage.
- Pas d’audio tiers fourni par défaut : importer un fichier autorisé puis activer chaque prière. La date hégirienne est un calendrier calculé, ajustable. Le corpus initial contient sept versets d’invocation sourcés, sans hadith inventé ni audio attribué artificiellement.
- Une seule animation prioritaire à la fois ; la première règle correspondante est choisie. Pas encore de conditions multiples ni d’éditeur de scènes avancées. Un test manuel peut écouter/afficher une règle désactivée pour en vérifier le média ; les événements automatiques respectent son interrupteur et son repos.
- Stockage JSON chiffré atomique adapté à cette version, pas encore Room/DataStore. Sauvegarde plafonnée à 256 Mo et 100 Mo par média ; pas de secrets dans le ZIP. Le code et la structure sont préparés pour une migration de stockage ultérieure.
- La signature fournie est une signature de développement, pas une publication Play Store. Même package et clé que l’APK de diagnostic pour cette mise à jour. Les builds CI utilisent une autre clé locale et ne sont pas des mises à jour signées de cette APK.

- Mises à jour : Internet et une URL de manifeste accessible sont nécessaires. Une confirmation dans l’installateur Android reste obligatoire ; l’application ne contourne pas cette protection. La source GitHub publique fonctionne sans compte ; une URL privée doit être remplacée par un emplacement accessible. La même clé est indispensable aux futures APK.
- Météo : service extérieur Open-Meteo, localisation approximative ponctuelle ou ville choisie. Les données peuvent être indisponibles ; le cache est daté. L’accès réel au service météo est bloqué par le proxy du cloud de développement (HTTP 403), donc pas validé de bout en bout ici. La tablette utilise sa propre connexion Internet.
- Interrupteurs retirés du menu et des widgets. Les anciennes données restent lisibles pour compatibilité ; aucune commande n’est proposée. Home Assistant n’est ni installé ni connecté dans cette version.
- Le scan approfondi /24 vérifie DVRIP et RTSP ; il n’effectue pas une recherche ONVIF unicast. Le nouveau test des ports vérifie la joignabilité TCP seulement. La découverte ONVIF standard continue d’utiliser WS-Discovery. Une fréquence Wi-Fi différente ne prouve pas une isolation réseau.

- Coran : sept récitations référencées dans le catalogue initial, API MP3Quran et URL personnelle HTTP(S) MP3/AAC/HLS. Pas de fichier audio religieux distribué ni de lecture hors ligne sans serveur local. Un fournisseur peut déplacer ou retirer ses fichiers. Le catalogue initial indique une source, pas un test en direct des 798 fichiers. Les API/audio officiels sont bloqués par le proxy cloud ; le test de lecture utilise un vrai flux de test local avec un son synthétique, sans prétendre entendre une récitation réelle.
- L’audio reste actif en veille/arrière-plan après l’action Lecture et s’arrête par le widget, l’écran ou la notification. La notification dépend des permissions Android ; l’adhan interrompt le Coran, sans reprise automatique. Aucune commande de lecture à distance ou reprise après panne n’est ajoutée.
- Prévisions : trois jours futurs selon les données disponibles ; conseils vestimentaires indicatifs. Pluie ou ressenti indisponibles restent marqués manquants. Les dates du cache sont visibles.
- Actualités : flux Franceinfo/Google Actualités ou RSS personnels. La recherche locale par nom de ville peut inclure des mentions hors de la commune. Affichage des titres seulement ; lecture de l’article dans le navigateur. Les API RSS sont bloquées par le proxy du cloud, donc accès réel à vérifier sur la tablette. Aucun titre fictif n’est préchargé comme actualité.

- Citrouille : détecteur frontal Android embarqué, sensible à la pose, lumière et taille du visage ; il détecte un visage, pas le corps d’une personne ni son identité. La caméra virtuelle ne prouve pas le suivi d’un visiteur. Le sens du regard, la fluidité OpenGL et l’autonomie Android 16 restent non vérifiés sur le matériel réel. Plusieurs visages peuvent provoquer un changement de cible, le plus grand étant retenu. L’overlay est transparent sur l’application, pas une superposition au-dessus des autres applications. Le mode automatique remplace temporairement la veille sombre et consomme plus ; il est désactivé par défaut.
- La timeline dépend de la durée et de la déplaçabilité annoncées par Media3/serveur. Une radio en direct n’offre pas forcément de déplacement. Les nouveaux boutons règlent le volume applicatif ; un volume média Android nul garde l’audio silencieux.
